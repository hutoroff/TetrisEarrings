# TetrisEarrings — electronics

KiCad project generated by scripts; Altium Designer imports it natively.

| File | What |
|---|---|
| `TetrisEarrings.kicad_sch` / `.kicad_pro` | Schematic (single A2 sheet, all symbols embedded) |
| `TetrisEarrings.kicad_pcb` | PCB, 24 × 48 × 0.8 mm, 4 layers, fully routed |
| `TetrisEarrings.pretty/`, `fp-lib-table`, `sym-lib-table`, `.kicad_sym` | Project libraries (the two pad footprints; everything else is KiCad stock) |
| `BOM.csv` | Bill of materials, grouped by value/package |
| `fab/` | JLCPCB upload: Gerber+drill zip, BOM, CPL (pick-and-place) |
| `gen_schematic.py` | Schematic + BOM generator (Python 3, stdlib) |
| `gen_pcb.py` | Placement, fixed front copper, plane fanout (Python 3 + KiCad footprint libs) |
| `route.py` | Autorouting of the back-side signals with Freerouting (run with KiCad's Python) |
| `export_fab.py` | Gerbers, drill, BOM, CPL → `fab/` |

## Regenerate

```sh
python3 hardware/gen_schematic.py        # schematic + BOM
python3 hardware/gen_pcb.py              # board: placement, LED copper, fanout vias (unrouted signals)
/Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3 hardware/route.py
python3 hardware/export_fab.py           # fab/ outputs
kicad-cli pcb drc --refill-zones --schematic-parity hardware/TetrisEarrings.kicad_pcb
```

`route.py` needs Java 17+ and `freerouting-1.9.0.jar` in `~/.cache/freerouting/fr-1.9.0.jar` (github.com/freerouting/freerouting/releases). A small Freerouting window appears while it routes. Freerouting 2.x ignores the pass limit in headless mode and never saves its result. Hand edits made in KiCad/Altium are lost on regeneration: either keep changing the scripts, or stop regenerating and treat the `.kicad_pcb` as the source from then on.

## Open in Altium Designer

1. **File → Import Wizard → KiCad Design Files** (Altium 21 or newer).
2. Add the `hardware/` folder (or the `.kicad_pro`), Next through the defaults, Finish.
3. Altium creates `TetrisEarrings.PrjPcb` with one `.SchDoc`. Run **Project → Compile** — it should report no errors; the sheet uses power ports and net labels on pin stubs, which the importer maps 1:1.
4. Optional: `kicad-cli sch export pdf TetrisEarrings.kicad_sch` for a PDF, or open in free KiCad.

## Circuit

**Power.** 1S Li-Po (602030, 300 mAh, with PCM) → `VBAT`. P-MOSFET Q1 (AO3401A) is the high-side switch producing the switched rail `VSW`, which feeds the LEDs directly (3.5–4.2 V, inside WS2812B-2020 spec) and the 3.3 V LDO U3 (ME6211) for the MCU.

**Soft latch** (matches `work.c`). Q1 gate is pulled to `VBAT` by R1 (off). Q2 (2N7002) pulls it low when `LATCH` is high; `LATCH` is the OR of the button (`KEY` via D1) and PA6 (`PWR_ON` via D2), R2 pull-down. Sequence: press → Q2 → Q1 → LDO → MCU boots, reads the button HIGH, sets PA6 = 1 → latch holds after release. PA6 = 0 (long press or low battery) → power drops; firmware spins in `while(1)` waiting for it.

**Button.** SW1 between `VBAT` and `KEY`, R3 100k pull-down (PA7 has no internal pull, pressed = HIGH). `KEY` → PA7 through R4 33k / R5 100k = 0.75·VBAT: 3.16 V at 4.2 V (≤ VDDA + 0.3), 2.6 V at 3.5 V (≥ 0.7·VDD).

**Battery sense.** R7 62k / R8 100k from `VSW` to PA1 (ADC_IN1), C11 filter. Firmware cutoff is 2700/4096 · 3.3 V = 2.175 V → **3.52 V** battery. On `VSW`, so no drain when off. Tune R7: 68k → 3.65 V, 56k → 3.39 V.

**Charger.** MCP73831-2 (4.2 V), input from two dock pads J2 (`VCHG` 5 V, GND — the printed stand acts as the dock), R9 6.8k → ~150 mA (0.5 C), D3 charge indicator. The charger connects straight to the battery, so charging works with the earring off.

**LEDs.** 60 × WS2812B-2020, DIN of LED1 from PA9 (TIM1_CH2) via R6 330 Ω. Chain order equals the firmware index from `GetLEDIndex()`: row 0 is the bottom row, even rows run right→left, odd rows left→right; LED*n* has index *n*−1. C12 10 µF bulk plus one 100 nF per row (C13–C22).

**MCU.** STM32F070F6P6 TSSOP-20, 8 MHz crystal Y1 with 12 pF loads (`ponytail:` set to the crystal's CL), BOOT0 10k to GND, NRST 100 nF, SWD via Tag-Connect TC2030 pads (J1). PA0, PA2–PA5, PA10, PB1 unused; PA3/PA4 (`Led1`/`Led2` in the `.ioc`) are initialised by firmware but never driven, so they are left unconnected.

## PCB layout

**Stackup** (JLC 4-layer, 0.8 mm):

| Layer | Contents |
|---|---|
| F.Cu | LEDs, data chain, power rails |
| In1 | GND plane |
| In2 | VSW plane |
| B.Cu | all other parts and signal routing |

The rules are the JLC standard: 0.15 mm track and clearance, 0.45/0.2 mm vias, 0.3 mm copper-to-edge.

**Front (jewellery face).**
- The LEDs sit on a 3.5 mm grid, and odd rows are rotated 180° so each DOUT→DIN hop is a short jog.
- Each gap between rows carries one power rail, alternating VSW and GND. Each rail hugs the row below it, which leaves a band where signal vias fit.
- The rails reach the planes only through vias in the board-edge strips (GND on the left, VSW on the right). This keeps the back free of a via grid.
- There is no silkscreen on the front, and there are 2 dock pads at the bottom edge.

**Back.**
- MCU in the middle, with the crystal right against PF0/PF1.
- Soft-latch parts near the top, and the button at the top edge so it stays accessible.
- Charger at the bottom, next to the Tag-Connect footprint (it has 3 NPTH alignment holes).
- Battery pads on the left edge. Glue the 602030 pouch over the back parts with kapton tape in between; the button and SWD pads stay uncovered.
- Every back-side GND/VSW pad has its own fanout via to its plane.
- 0.8 mm earring-hook hole at the top.

**Assembly.**
- JLC assembles both sides from `fab/`.
- BT1 is excluded from the CPL; solder the pouch tabs by hand.
- J1/J2 are bare copper.
- JLC's CPL preview sometimes shows parts rotated (a known library-orientation quirk, typically on SOT-23 and TSSOP). Check the rotation preview on the order page before paying.

## Power budget / battery choice

WS2812B-2020 idle current ≈ 0.6–0.7 mA each → ~40 mA for 60 LEDs, MCU ≈ 8 mA, lit-LED average ≈ 8 mA (effects stay ≤ ~25 % per channel) → **≈ 55–60 mA**. 300 mAh usable to 3.5 V ≈ 4.5 h. For more margin use 602535 (400 mAh, ≈ 6 h) — same pads, BOM change only.

Footprints `TetrisEarrings:Pad_Battery_2x` and `Pad_Dock_2x` are placeholders for two solder pads each; draw them to the pad/contact geometry of your dock.
